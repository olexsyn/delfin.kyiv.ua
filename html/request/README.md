# request/idx.htm


Був невеличкий глюк. Після надсилання форми, якщо повернутися назад на сторінку з формою, то номери телефонів є у полях вводу, але при повторній відправці пише: "Вкажіть хоча б один номер телефону повністю;" Достатньо стерти останню цифру і написати її знову - і валідація проходить.
Хоча це не є нормальною поведінкою користувача, який заповнює і відправляє форму, але є вирогідність того, що він може захотіти виправити форму і повернеться назад і зіштовхнеться з незрозумілою помилкою. (Наприклад це також зручно для мене при тестуванні).

Це класична проблема синхронізації стану IMask з DOM. Коли браузер відновлює значення поля через кнопку "Назад" (bfcache) або автозаповнення форми, він напряму підставляє текст у `value` інпута — минаючи події `input`, на які реагує IMask. У результаті в самому інпуті номер видно, а внутрішній стан маски (`masked.isComplete`) лишається "порожнім", доки ви не введете хоч один символ вручну — тоді IMask перечитує значення і синхронізується.

Рішення — примусово синхронізувати маску зі значенням поля при показі сторінки (подія `pageshow` спрацьовує і при звичайному завантаженні, і при поверненні з bfcache):Спрацює і для звичайного завантаження сторінки, і для повернення кнопкою "Назад" — в обох випадках `pageshow` викликається, а `updateValue()` перечитує актуальний текст із поля та оновлює `masked.isComplete` відповідно.

Тому був доданий цей код:

```javascript
	// Синхронізація стану маски зі значенням поля, якщо браузер
	// відновив форму з кешу (кнопка "Назад") або автозаповнення —
	// в цьому випадку value змінюється напряму, без події input,
	// і IMask про це "не знає" без примусового updateValue().
	window.addEventListener('pageshow', () => {
		par1phoMask.updateValue();
		par2phoMask.updateValue();
	});
```
